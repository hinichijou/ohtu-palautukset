### Minkälaisen ohjetiedoston agentti generoi, ja mitä jouduit korjaamaan?

Agentti loi englanninkielisen tiedoston, jossa oli aluksi 23 riviä kolmella väliotsikolla. Tekstissä ei ollut nähdäkseni varsinaisesti mitään virheellistä. Pyysin agenttia lisäämään sen, missä käyttäjätunnuksen ja salasanan validointi tapahtuu. Pyysin agenttia tarkentamaan eksplisiittisesti, että kyseessä on uv projekti, vaikka tämä tuli jollain tasolla esiin jo aiemmassa vedoksessa. Pyysin agenttia tarkentamaan, että ohjelma tulisi avata taustalle ennen testien ajamista. Pyysin agenttia vielä varmistamaan, että virtuaaliympäristö on aktivoitu ennen kutsujen suorittamista, koska sillä oli aluksi odottamattomia ongelmia terminaalikomentojen suorittamisen kanssa (en ole vieläkään ihan varma mistä ongelmat johtuivat, ongelma saattoi olla omassa VS Code konfiguraatiossa). Muokkasin tiedostoa niin, että pyysin agenttia korjaamaan sen itse esimerkiksi promptilla "Is it clear based on the AGENTS.md that the application should be running before running the tests with uv run robot src/tests? If not, update the instructions to reflect this". Ajattelin, että agentti tuottaa itse tekstiä, jota se parhaiten ymmärtää.

### Noudattiko agentti pyyntöä kirjoittaa testit ennen toteutusta?

Noudatti. Selitin ensin agentille, että annan sille seuraavaksi user storyja ja sen tulee kirjoittaa ensin Robot Framework testit tiedostoon register.robot ja varmistaa etteivät uutta toiminnallisuutta testaavat testit mene läpi ja kirjoittaa toiminnallisuus vasta tämän jälkeen niin että testit menevät läpi. Agentti kuittasi tämän ja antoi askeleet, joita noudattaen se aikoo suorittaa annetun tehtävän.

### Kuinka paljon jouduit ohjaamaan agenttia matkan varrella?

Enemmän kuin odotin. Itse toiminnallisuuden ja testien sisältöjen kanssa ei ollut ongelmia, agentti toteutti user storyt nähdäkseni täydellisesti. Agentti yritti ajaa testit komennolla `uv run robotcode robot src/tests` vaikka `AGENTS.md`:ssä spesifisesti mainitaan `uv run robot src/tests`, kun kysyin, että miksi, agentti vastasi että "Hyvä kysymys". Agentilla oli useampaan otteeseen vaikeuksia löytää uv komentoa syystä mikä minulle ei ihan auennut (liittyi ehkä omaan VS Code konfiguraatiooni, jota sitten korjasin), jota se koitti korjata mielestäni vähän kyseenalaisilla ehdotuksilla. Agentti ei tuntunut osaavan odottaa testien valmistumista vaikka koitin ohjata sitä ottamaan huomioon viiveen testien suorituksessa. Lopussa agentti sanoi, että testit on aloitettu, kysyin siltä, että voiko se ilmoittaa, kun testit ovat valmiit, johon se vastasi, että se ei voi lähettää itsenäisesti uutta viestiä. Kysyin sitten vähän ajan päästä että ovatko testit valmiit, johon agentti vastasi, että kyllä, testit menivät läpi ilman virheitä. Huomasin lopuksi, että agentti oli jättänyt serverin pyörimään taustalle ja se piti pyytää erikseen sulkemaan se. `AGENTS.md` jäi tässä mielessä puutteelliseksi, koska siinä ei selkeästi ilmaista, että serverin tulisi olla käynnissä ainoastaan testien ajon ajan.

Testit hajosivat, kun rikoin toteutuksen tarkoituksella.

### Mitä muuta opit?

`AGENTS.md` oli itselleni uusi asia. Luulen, että tiedostoa hiomalla voisi saada agentin toimimaan monimutkaisemmissakin toimintaympäristöissä ja suorittamaan monimutkaisempia tehtäviä. Agentin ohjastaminen oli työläämpää mitä odotin edellisen tehtävän kokemusten perusteella. Ajoympäristöön liittyvien ongelmien korjaaminen on ärsyttävää, koska agentti saattaa tehdä ihmeellisiä ratkaisuehdotuksia ja agentin prosessi katkeaa aina, jos näihin tekee jonkun korjauksen ja se pitää pyytää aloittamaan prosessi uudelleen siitä mihin se jäi. Agentti ei tuntunut toimivan hyvin testien viiveiden kanssa, en tiedä olisiko sen saanut keskustelemalla ja ohjaamalla toimimaan testien kanssa paremmin yhteen. Näiden kokemusten perusteella käyttäisin agenttia mielummin puhtaana koodausavustimena ja ajaisin testit mielummin itse. User storyjen toteuttamisessa agentti oli hyvä ja ratkaisut noudattivat projektin rakennetta ja tyyliä.
